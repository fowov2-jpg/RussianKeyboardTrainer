# GitHub CI: матрица испытаний русского IME

> Обновление rc4: обученная RUPunct включена в обычный APK и автоматический
> анализ IME. Добровольный сервис Android предоставляет видимый контекст.
> [Актуальное поведение и проверки rc4](AUTOMATIC_KEYBOARD_RC4_RU.md).
> Ниже сохранён документ предыдущего этапа; отметки «ещё не включено»
> и исторические CI-ссылки не являются статусом rc4.


Каждый результат проверяется по конкретному commit SHA; нельзя выдавать успешную
проверку предыдущего коммита за проверку текущей версии.

В rc2 `android-build` дополнительно требует реальную проверку Kotlin-движка
на всех 1 000 000 парах и 100 000 разных словоформ из тестового корпуса,
совпадение хешей и наличие несжатого mmap-индекса с лицензиями в каждом APK.
Новые instrumentation-сценарии проверяют загрузку asset, выбор подсказки,
«Оставить» и отсутствие повторной автозамены после Undo. Наличие/компиляция
сценариев не означает, что они выполнены на устройстве.

| Workflow | На чём | Что реально проверяет |
| --- | --- | --- |
| `validate` | Ubuntu Python 3.11 | unit tests, duplicate-safe split, 1-epoch listwise demo train, KEEP calibration, экспорт FP32/INT8 ONNX, ONNX Runtime на CPU, форму выходов и численную близость |
| `android-build` | Ubuntu + SDK 35 | Kotlin JVM unit tests, Android lint, сборка debug APK, а также компиляция Android instrumentation APK без запуска эмулятора — для раннего обнаружения ошибок в `androidTest` |
| `android-emulator` | Android emulator API 35 / 3072 MB | Instrumentation: manifest/IME permission/no INTERNET, активность с полем ввода, вызов корректора на Android runtime, регистрация IME, реальный набор с автозаменой после пробела и Undo по Backspace |
| `android-onnx-smoke` | Android emulator API 35 / 3072 MB | Временная упаковка синтетической INT8-модели, численное сравнение Python и Android, Kotlin-токенизация, P50/P95/max и процессная PSS; строгая проверка, что instrumentation не пропущен |

## Просмотр результата

GitHub → Actions → выберите workflow и последний запуск **для текущего commit SHA**.
Во вкладке Artifacts доступны APK, Python-модельные метрики и Android test reports.
Android emulator workflow запускается на Pull Request и вручную (`workflow_dispatch`).
Для образа Android 35 оба workflow делают до трёх попыток скачивания с проверкой
`source.properties`: периодически GitHub SDK отдаёт повреждённый ZIP, до запуска
самого приложения. После исчерпания попыток CI должен показывать failure — не
считать устройство протестированным. Замеры сохраняются только при реально
выполненном тесте; эмулятор не является заменой физическому смартфону.

## Что НЕ покрыто

- Автоматизированный тест ввода использует эмулятор и UiAutomator. Он покрывает короткий happy-path и Undo после автозамены; составление текста, выделения, длинная история и прочие сценарии InputConnection пока не проверены.
- При сбое отображения IME тест повторно касается реального поля и запрашивает открытие клавиатуры, но НЕ пропускает проверку: если клавиши не появятся, CI будет красным. Если UI скрыт сторонним ANR **Pixel Launcher**, тест один раз закрывает именно это системное окно и восстанавливает видимость MainActivity; собственный сбой клавиатуры никогда не игнорируется. Для диагностики сохраняется дамп InputMethodManager, состояние окон и снимок только искусственного тестового экрана.
- Точность русских исправлений на независимом корпусе, метрики ложных исправлений.
- В Android APK интегрирован ONNX Runtime, но в обычную сборку **не включаются веса синтетической модели**. Только отдельный smoke workflow временно добавляет их в test APK. Автоматическая нейросетевая коррекция в IME ещё не включена.
- Физические смартфоны с 3–4 ГБ: батарея, нагрев, P50/P95 отклика, реальная PSS IME.
- Реконструкция адресата, русский контекстный род и streaming punctuation.
- Эмуляторный `dumpsys meminfo` относится к тестовому запуску Activity, а не замеру
  нагрузки при реальном наборе текста. Размер RAM AVD не гарантирует поведение
  бюджетного чипа с такой же памятью.

## Политика безопасности CI

Не сохранять личные сообщения/клавиатурные логи в GitHub artifacts. Для тестов
используются исключительно синтетические строки. Секреты не передаются в fork PR.
Для автоматических исправлений в чувствительных полях запрет на чтение контекста
проверяется статической логикой TextFieldPolicy и unit-тестами.


- На небольшом API 35 эмуляторе после первого фокуса и изменения размера окна нельзя повторно вызывать UiAutomator.click() на старом объекте поля: координаты могут попасть на клавишу. Тест один раз касается актуального поля, повторно запрашивает IME только через UI-поток и **проверяет пустоту редактора до первого целевого нажатия**. Для MainActivity и инструментального сценария включён ADJUST_RESIZE.

- Перед физическим нажатием на поле инструментальный IME-тест сначала проверяет, не открылась ли клавиатура автоматически. Если она уже показана, тест **не** нажимает на возможные устаревшие координаты EditText, которые ранее случайно вводили букву `г`. Далее тест отдельно требует чистый редактор перед реальными нажатиями.
