# Экспериментальный Context Ranker в Android

Модель Python `ContextRanker` экспортируется в ONNX FP32 и INT8.
Класс `OnDeviceRanker` в Android загружает `ranker_int8.onnx`,
`ranker_metadata.json`, `tokenizer.json` из локальных assets.
Токенизатор Kotlin повторяет Python `CharTokenizer.encode_pair`, включая
бюджет контекста и специальные токены; Android instrumentation сравнивает
численные оценки с Python ONNX Runtime.

## Безопасность и расход ресурсов

- В стандартную сборку модели не входят: `openIfBundled` возвращает null.
- Прототип IME **не запускает** нейросеть после каждого пробела. Его
  пользовательская коррекция пока локальная и детерминированная.
- В `android-onnx-smoke` GitHub CI обучается **искусственная** мини-модель на
  демонстрационных предложениях, после чего она временно упаковывается в
  тестовый APK для проверки загрузки и математической совместимости.
- Нет INTERNET-разрешения. ONNX сессия на одном CPU-потоке, закрывается после
  теста. Размер модели ограничен 16 МБ.
- Нет утверждений об уровне качества Gboard/Apple, соответствии русской
  грамматики или низком потреблении энергии на реальном смартфоне.
- **Не применять** выходы синтетической модели для автоматического исправления
  пользовательского текста. Перед включением нужны независимый корпус, FCR,
  калиброванный KEEP margin и замеры P95/PSS на бюджетных телефонах.

## Проверка

GitHub Actions → workflow `android-onnx-smoke`. В нём включён режим
`ONNX_ONLY=1`: выполняется исключительно тест модели, а не UiAutomator-тест
экранной клавиатуры, который проверяется отдельным workflow. Тест
`OnDeviceRankerTest.quantizedOnnxScoresMatchPythonOnTheEmulator` сравнивает
скоринги INT8 CPU Python и Android с допуском 0.08. Если модель не упакована,
тест пропускается в обычной Android-сборке; отдельный smoke workflow обязательно
упаковывает assets перед запуском. После instrumentation специальный Python
валидатор проверяет XML-отчёт и **завершает workflow ошибкой, если тест пропущен,
не найден, провалился либо не выполнился**. Тест сравнивает также входные
идентификаторы токенизатора и маску внимания с Python, а не только скоринги.

Контрольный путь к APK теста: `android/app/build/outputs/apk/debug/app-x86_64-debug.apk` на эмуляторе; мобильные APK выпускаются отдельно для `arm64-v8a` и `armeabi-v7a`
внутри workflow. Этот артефакт **не является пользовательским релизом**.

## Экспериментальная оценка скорости / RAM

В `android-onnx-smoke` дополнительно замеряются загрузка сессии,
40 повторных вызовов после 5 прогревов (P50/P95/max) и PSS процесса
перед загрузкой, после загрузки, после вызовов и после закрытия сессии.
Результат: `reports/emulator/onnx-benchmark.json`, опубликованный
в GitHub Artifacts и Job Summary. Данные из `Logcat` содержат только
числовые метрики синтетической модели, не пользовательский ввод.

**Ограничения:** PSS — память процесса целиком, а не весов модели; эмулятор
с выделенными 3 ГБ не эквивалентен бюджетному физическому смартфону.
Тестовая модель маленькая и искусственно обученная, поэтому её
P95 нельзя экстраполировать на будущую качественную модель.
